# v2.32.117 息屏背光修复

## 原因

息屏逻辑原来通过 `lcd_display_set_brightness(0)` 关闭背光；这个函数同时
覆盖了用户亮度变量。之后音量保存、亮度保存或重启会把临时的 0 当成用户设置，
造成配置中的 `brightness=0`。UI 和 LVGL 任务仍在运行，但屏幕一直黑。

## 修复

- `lcd_display_set_brightness()` 只改变用户亮度，并在当前未息屏时更新 PWM。
- 新增 `lcd_display_set_backlight_suspended()`，息屏只切换临时背光状态，
  不改用户亮度。唤醒、息屏禁用和超时设为 0 均通过该接口恢复背光。
- 亮度状态访问使用静态互斥锁，避免 UI、网络和 LVGL 空闲任务同时改 PWM。
- 音量保存时读取到的是用户亮度，不会再把当前息屏状态写入 `mori_system.ini`。

## 实机验证

- 当前板：ESP32-S3 COM26，MAC `a4:cb:8f:f2:c4:c0`，v2.32.117。
- 修复前配置曾为 `brightness=0`；先通过 HTTP 恢复为 128。
- 修复版自然等待 1 分钟后：`screen_dimmed=true`，背光关闭但 UI 仍运行。
- 发送一次 `key b` 后：`screen_dimmed=false`，页面保持主页，状态线程继续运行。
- 息屏前后无烧录、补丁或音乐任务；音量保持 1%。
- 主机回归：亮度 128/77/0，息屏、息屏中调亮度、唤醒及初始化失败路径均通过。
- 设备 app 已刷写，esptool `Hash of data verified`；完整包已重新生成。
