# 烧录协议优化核查与块命令草案

2026-09-09。依据ESP32源码、`example/logic/bacon.v`和51c9db4实机记录；本文件是设计评审材料，尚未实现、综合或刷入新CPLD协议。SPI40MHz、CPU160MHz保持固定。

## 当前数据路径

ESP32 → SPI → `bacon_legacy_core` → 卡带A/AD、CS、RD、WR。

`example/logic/bacon.v`直接在SPI时钟沿解析位流并更新卡带控制线，AHB接口目前仅保留外形，没有块编程执行引擎。因此本地轮询或自动写脉冲需要修改CPLD逻辑，不能只修改ESP32发包。

CS0模式的首字节同时编码批处理长度、方向和控制电平。长度最大3字节，属于总线操作打包；不是可连续接收ROM原始数据的FIFO。

现有标准AMD缓冲写的每个16位字为：

```
数据操作字节 | 数据低8位 | 数据高8位 | WR拉低 | WR拉高
```

此外还有解锁、缓冲入口、字数、地址和确认命令。生产代码计算`seq_len = 57 + 5 * write_words`，512字节ROM对应256个字，共1337字节SPI数据。随后另行发送状态读取和复位事务。

不能直接删掉末尾WR拉高字节：CPLD在批次完成时才更新控制线，新数据与WR上升沿的先后关系会改变，可能违反Flash写入所需的数据保持时间。地址自增模式也不能替代自动写脉冲，且会改变总线模式。

## 可核算的空间

| 指标 | 当前512字节写入包 | 块命令示例 |
| --- | ---: | ---: |
| 数据字节 | 512 | 512 |
| 命令和数据合计 | 1337 | 528（假设16字节头） |
| 有效载荷比例 | 38.29% | 96.97% |
| 40MHz SPI连续传输时间 | 267.4us | 105.6us |

以上只计算请求包线速，不含回复、CS间隔、软件调度和Flash内部忙时间。

龙珠16MiB实测实际编程28293个512字节块，另有2291200字节全FF跳过。在同一块数下，请求包从37827741字节降到14938704字节，理想线速时间从7.566秒降到2.988秒，节省约4.578秒。此为模型推算，不是新协议实测结果。

当前无补丁实测编程阶段25.673秒，其中命令发送9.047秒、完成轮询11.807秒、组装1.381秒、复位1.268秒；这些计时仍含软件开销。轮询11.807秒同时包含Flash实际忙时间，不能全部当作可消除开销。擦除另占33.053秒，协议压缩也不能直接消除它。

## 建议实现顺序

1. **块写入命令。** ESP32发送地址、长度、数据和校验，下位机产生完整AMD解锁/缓冲写/确认序列以及满足时序的写脉冲。先支持当前验证过的标准AMD卡；特殊AMD、Intel、GBX继续旧路径。
2. **本地完成检测。** 下位机执行DQ7确认、DQ5临界重读、超时与复位，向ESP32返回明确结果。失败回复包含地址、状态字、失败阶段和序号。减少SPI往返，不省略Flash完成检查。
3. **双缓冲。** 采用两块512字节数据缓冲；Flash处理块N时，SPI接收块N+1。只有完整收包且CRC正确的数据可执行；队列满时返回busy/credits，绝不能覆盖未执行数据。该设计需要至少1024字节数据存储，实际资源与时序须经综合/布局布线确认。

同一Flash的擦除与编程并行不包含在首版范围内。只有明确支持并验证擦除挂起或独立bank操作的芯片，才能另行设计该流程。

## 首版命令契约草案

16字节请求头示例：版本1B、操作码1B、标志1B、时序/命令配置编号1B、序号2B、数据长度2B、当前bank内字节地址4B、CRC32 4B；所有多字节字段采用小端。CRC覆盖前12字节头及payload，确切算法参数、操作码与协商封装需实现前冻结。

- `CAPS`：协议版本、支持的命令配置、最大块大小、缓冲个数和状态能力。
- `PROGRAM_BLOCK`：偶数地址和长度、不跨Flash缓冲页/扇区/bank边界，首版最大512字节。非法范围/长度/CRC不得触发写脉冲。
- `STATUS`：accepted/running/done/error，返回序号、已完成地址、错误类型、原始Flash状态及可用队列槽位。接收成功与Flash编程成功必须区分。
- `ABORT`：丢弃未执行队列；当前已开始的Flash操作按器件允许方式完成或复位后才报告停止，不假装撤销已写字节。
- 丢失回复后通过序号查状态；重复序号不得盲目重复编程。掉电后的会话必须重新协商，不能沿用旧队列。

旧协议三个CS组合已有用途，不能随意借用一个“空闲通道”。能力探测必须先在旧RTL中证明只产生安全空闲操作，不切电、不拉低WR、不改变卡带内容；未得到匹配版本/签名的设备继续旧协议。探测序列及进入扩展模式的精确编码是实现前的必需设计项，当前草案不把任意魔术字节当作安全探测。

## 从设计到实机的验证要求

- RTL仿真比较旧/新引擎输出的地址、数据、解锁序列和WR/RD建立保持时间；覆盖512字节、短尾块、缓冲边界、取消、CRC错、短包、队列满、超时及D0/D1命令映射。
- 验证SPI接收时钟与本地执行时钟之间的数据交接；异步FIFO或握手必须防止重复执行、漏块及复位后旧数据重放。
- 冻结ESP32与CPLD对应版本后，走完整下位机构建流程，检查实际资源、时序、引脚和打包产物来源；现有`example/`源码不能直接证明与机上已烧录二进制完全一致。
- 上板先能力读取与只读总线验证，再短范围擦写/读回，最后同ROM全16MiB无补丁/SRAM烧录、取消恢复及全量读回。保留原协议回退与当前已验证固件。

首版目标应是可验证的块写、本地等待和错误恢复；不预设“整体2.5倍”或保证某个MB/s数字。
