# v2.32.112：统一 dump 与逐字节校验

## 结论与原因

当前 GBA/GBC 已经共用 dump 路径；历史的 PSRAM 分片、临时文件再合并路径仍留在源码，
但没有调用。本轮没有在 v2.32.111 上复现历史乱码：两张卡的 32 MiB dump 均通过
原 Bacon / CPLD 交叉全量比较。不能将历史损坏直接认定为本轮发现的性能问题。

确认的性能问题是：默认 64 KiB malloc 缓冲进入 PSRAM，而 S3 的 SDMMC 不能直接 DMA
访问 PSRAM。ESP-IDF 5.5.1 `sdmmc_write_sectors` 对这种缓冲逐个 512 字节扇区搬运并写入，
使 32 MiB dump 的 TF 写入约耗时 102–103 秒。

另外实机复现了校验误报通过：从当前 GBA 卡备份生成 65536 字节测试文件，仅把
0xBD 从 0x56 改为 0x57，旧版仍返回 `verify finished`，因为比较前自动修正了文件头。
新版准确报告 `verify mismatch @0x000000BD 57->56`。

## 实现

- 删除未使用的 PSRAM 分片/合并路径，用 `burner_dump_stream.c` 统一双缓冲生命周期。
  两个 PSRAM 槽交替接收卡带数据；提交给 TF 写线程的槽在完成前不能复用。
- TF 写线程持有固定 16 KiB 内部 DMA 缓冲，批量复制后同步写 TF。上一笔完成才复用 DMA 缓冲。
  创建缓冲/线程失败直接报错，不退成单缓冲或另一条隐式写入路径。
- 提交接口检查 in-flight 状态；结束/取消时先收回写入请求，再关闭文件和释放内存。
  只有全部数据写完且 close 成功才将 `.dump_tmp` 改名为最终文件。
- `burner_verify_stream.c` 统一 GBA/GBC 校验：卡带每次批量读 64 KiB 到 PSRAM，完成后
  用 8 KiB 内部 DMA 缓冲读取 TF 并逐段比较。保留实体卡带 bank 映射与原 SPI 接收完成语义。
- 比较严格采用文件原字节，不自动修头、不补末尾字节、不在不匹配后换读法再试。
  GBA 校验不再向上取整文件长度，超出卡容量明确报错。GBC 的首个差异日志继续保留。
- GBA 烧录本身的补丁/文件头处理未改；校验烧录后的补丁数据时，仍应选择对应预期文件。
- 原 Bacon 格式、CPLD 扩展、AG32 batch、40 MHz SPI 均未改。

## 32 MiB 实机对比

COM26，ESP32-S3 MAC `a4:cb:8f:f2:c4:c0`，HTTP `192.168.1.134`。
USB 连接，同一 TF 卡，烧录核心配置保持原值；串口由每个测试独占。
计时采用设备 `task_time_ms`，dump 包括写 TF 和最终关文件，不包含独立校验任务。

| 卡带 / 条件 | 旧 dump | 新 dump | 旧校验 | 新校验 |
| --- | ---: | ---: | ---: | ---: |
| GBA S29GL01GP/GS，前 32 MiB | 103.385 s | 25.997 s | 23.585 s | 22.260 s |
| GBC MX29GL256E/F，32 MiB | 104.569 s | 27.256 s | 25.109 s | 23.729 s |

两行均为 CPLD 路径、64 KiB dump 块，GBC 保持 3.3V。
GBA 卡 128 MiB，ID `01 00 7E 22 28 22 01 22`，D0/D1 不交换；GBC ID `C2 7E 22 01`、MBC5。
dump 约快 4.0 / 3.8 倍，校验耗时减少约 5.6% / 5.5%。校验改进还减少了内存占用并修正准确性。
读卡与写 TF 有重叠，`dump_wait_time_ms` 是等待写线程的时间，不能把这些分项相加当总耗时。

GBA 第一次旧版校验与 HTTP 下载重叠，该次 25.736 s 不用于性能表；之后无其它 TF 访问重测得到 23.585 s。
GBA dump 的 25.997 s 测于 v112 中间工件 CB03299F…，dump 代码与最终工件一致。
最终工件另外通过机身 4 MiB dump、32 MiB 全量校验及文件哈希核对；GBC 32 MiB dump 在最终工件上测得。

## 正确性与异常测试

- GBA/GBC 导出 33554432 字节，与优化前、经原 Bacon 交叉验证的备份 SHA256 完全一致。
- 最终固件：GBA 错误头 0xBD 精确报错；GBC 0x4000 bank 边界故意改字节后精确报错。
- 两种卡的 65537 字节文件比较通过，最后一个字节包含在比较中。
- 原生菜单：两种卡分别通过 4 MiB dump 和 32 MiB 参考文件校验，返回菜单正常；
  文件工作线程最小剩余栈 10640 字节，完成后内部空闲内存约 73 KiB。
- 生产 dump/verify 代码的主机测试覆盖延迟写入期间槽不可覆盖、32/64/128/256 KiB 块、
  512 字节/8 KiB/16 KiB/64 KiB 边界及奇数尾部、分配失败、写线程创建失败、读写错误、取消清理、
  第一个差异和文件截断不补齐。
- 实机通过 `/api/cancel` 取消在途 dump，终态 cancelled、processed=131072，工作线程退出，
  内部空闲内存恢复到取消前 73439 字节。测试的首次尝试误用了仅取消补丁的串口命令，
  那次 dump 正常完成，不算取消测试；随后改用实际 dump 取消 API 通过。
- 取消输出及其 `.dump_tmp` 均返回 404；已清理四个临时正/负测试文件及首次取消测试的完整输出，
  本地基准和测试样本仍可用于重建。两种卡的完整基线与优化后导出均保留。
- 构建及共享状态类型检查通过。没有擦除或编程任一卡带。

验证内存方案经过实际调整：初稿两块 16 KiB DMA 内存受内部堆连续空间限制而分配失败；
两块 8 KiB 虽可运行，但增加卡带会话次数。最终方案为单块 8 KiB TF DMA + 64 KiB 卡带 PSRAM，
既保留大块读取，又通过机身实际内存条件验证。中间方案数据不冒充最终方案结果。

本轮实机覆盖上述两张卡的前 32 MiB；未测试其它 Flash 配方、D0/D1 交换卡、GBA 的 32 MiB 之后区域。
芯片与 MBC 时序本轮未更改，不能由测试结果推断所有卡均已验证。
