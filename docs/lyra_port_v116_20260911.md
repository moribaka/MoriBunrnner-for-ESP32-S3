# MoriBurnner v2.32.116：Lyra 音频后端移植

从 moribaka 最新公开星标定位到 `coderkei/lyra-firmware`，不是另一个同名项目。
星标时间 2026-09-10T18:11:16Z；拉取到 F:/dev/esp32/lyra-firmware，固定引用

## 实现范围

移植 upstream `lyra_audio.cpp/h`，保留 Apache-2.0 版权和许可证，新增本机
I2S/存储适配层。许可证同时纳入 firmware assets/licenses/lyra.txt。
原 `music_player.c` 已替换，原 C API、机身按键 UI、网页控制接口继续调用
`music_player_lyra.cpp`。文件浏览器加入 M4A、OGG、Opus、AIFF/AIF/AIFC。

- 压缩输入预读 256 KiB、PCM 输出 ring 256 KiB，解码及输出分任务。
- 开始播放先填 DMA，auto-clear 保证欠载时送零而不是重复旧数据。
- 使用 Lyra 格式解析、FLAC seek、MP3 frame seek、Ogg packet 和 M4A sample table。
- 保留 upstream 音量渐变、输出幅度上限。均衡器内部为默认零增益，未新加 UI 功能。
- 本机只有一组 I2S：BCLK15 / WS16 / DOUT7，最终混成单声道送两个槽；
  输出 16 bit，24 bit FLAC 可以解码但不是 bit-perfect 输出。
- DMA 调整为 4 x 512 frame（8192 B），音频栈 16 KiB、输出栈 4 KiB。
  CPU 中间缓冲放 PSRAM，驱动 DMA 留在内部 RAM，适应本机其它模块的内存占用。
- 沿用 system.ini 音量持久化，未接入或运行 upstream NVS 初始化/擦除逻辑。
- 旧 API 按字节续播/快进通过时长比例适配到 Lyra 时间定位；旧 position 字段
  是时间比例折算，不再表示精确文件读取偏移。初始续播解析在后台任务执行。
- SMB 使用 funopen 适配现有 smb_client 的 read/seek/tell/close；目前设备未
  配置 SMB 连接，未完成实际网络歌曲播放资格验证。

upstream 的两处行为作了针对性修正：M4A AAC 从头播放也使用采样表读取，
绕过 simple parser 不支持 mdat-before-moov 的限制；正常结束插入一个完整
DMA ring 的零数据作为尾音排空屏障，低采样率排空不再被固定 2 秒强制删任务。
短音频预填剩余 DMA 描述符显式补零。其它格式仍受对应解码库支持范围约束。

构建沿用 ESP-IDF 5.5.1、esp_audio_codec 2.5.0；没有为移植升级全工程框架
到 upstream 的 IDF6.0.2/codec2.6.2，没有导入它的屏幕、触控或图片库。
烧录器、AG32、卡带协议、卡带频率均未修改。

## 测试过程

测试始终先确认音量 1%；合成样本再衰减 0.001 倍，停止后清理本轮 TF 文件。
测试代码 `tools/music_lyra_test.py` 生成不同格式，逐个播放、暂停、暂停时定位、
恢复、等待完成、停止，并检查状态错误及串口 panic。

第一版输出任务分配失败，已将 CPU 缓冲移至 PSRAM、缩小内部 DMA 占用。
第二版普通 M4A 报 mdat before moov，已应用上述 sample-table 路径。
第三版 10 种格式及控制序列通过，继续验证最后的排空收尾版本。
失败候选的记录保留在 build/music_audit*、build/lyra_test2、build/lyra_test3，
不将中间失败写成全部成功。

编译、共享类型一致性、Web 语法/轮询及 GBC 补丁隔离回归通过。
本轮没有采集模拟输出或 I2S 波形，状态和计数测试不能证明所有文件都无破音，
也没有拿到此前报告失败的那份 MP3。

生产代码改动边界已通过 Git 对照确认：`main/burner/core`、
`ws_server_http_burn.c`、`ag32_batch_programmer.c`、`example` 无差异。
`tools/SERIAL_DEBUG.md` 与 `.workbuddy/` 为现有用户改动，不纳入本轮提交。

## 最终结果

`lyra_v116_formats.json` 合并两次最终运行的 13 项结果，每项均经过播放、暂停、
暂停时定位、恢复、完成及停止：

| 样本 | 采样率 | 解码位深 |
|---|---:|---:|
| MP3 CBR / MP3 VBR / MP3 mono | 44100 / 48000 / 22050 | 16 |
| FLAC 16 / FLAC 24 | 44100 / 48000 | 16 / 24 |
| WAV / AIFF | 44100 | 16 |
| AAC M4A（mdat 在 moov 前） | 44100 | 16 |
| Vorbis OGG / Opus | 44100 / 48000 | 16 |
| WAV 低采样率 | 8000 | 8 |
| FLAC noise 24 | 96000 | 24 |
| ALAC M4A（faststart） | 44100 | 24 |

其中 FLAC noise 采用固定种子的低幅度噪声，避免只有静音/纯音造成极端高压缩率。
解码任务历史最低剩余栈 2764 B。部分完成边界记录 pcm-underruns=1，含义是
软件 PCM ring 一次为空，并非测得硬件 DMA 已欠载；不据此宣称零欠载或零破音。
最后一次矩阵上传 Opus 文件时遇到 HTTP 408（还未播放），故单独补跑余下五项；
第一次候选也有上传失败。上传错误与解码错误分开记录，没有自动重试代码。
原始日志在 build/lyra_final、build/lyra_final_remaining。

最终机身测试使用现有 Lazer Boomerang - Signals.mp3，音量1%。原先适配层
输出绝对路径导致目录历史不兼容，已将 snapshot 规范为 TF 相对路径。
音乐入口、菜单键、A 暂停/恢复、停止、返回主页均通过。随后从机身直接启动
历史歌曲也成功，position 前进，验证后台初始续播适配。
原生脚本曾错误断言 canvas 页的通用行数应大于零，以及遇到串口短读 JSON
截断；已分别按真实 UI 语义和读取超时修正测试，没有改写 UI 布局。
这次最后的路径适配仅改变 UI/API 文件路径，音频引擎与13项测试版本一致。

所有测试已停止，设备音量保留1%，游戏卡未擦写。SMB 未配置服务器，当前仅
完成适配及编译，未声称网络歌曲实测通过。上游支持范围外的 M4A/ALAC 布局
仍可能受 Espressif parser 限制。
