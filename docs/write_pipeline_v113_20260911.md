# v2.32.113 烧录扇区流水线与自动校验实测

本轮从本地提交 `641f4e6`（v2.32.112）继续。ESP32-S3 实机已更新至
v2.32.113；原始 Bacon 协议及 AG32 固件未修改，SPI 配置/实际频率均为
40 MHz。设备为单共享卡槽，GBC 与 GBA 测试按用户确认换卡后依次执行。

## 实现

- 标准 GBA/GBC 共用完整扇区引擎：PSRAM/pipeline 为双扇区缓存和常驻 TF
  读取任务，direct 为单扇区同步读取。删除旧大窗口、反复创建的预取任务和重复烧录循环。
- 比较的是应用补丁和 GBA header checksum 后的最终字节。相同扇区不擦不写；
  force 模式明确重写。空白判定检查完整内容，只有已经确认“非空且不同”的完整
  替换扇区才允许提前结束比较。编程跳过完整 FF 页。
- 部分扇区写入会读全旧扇区并保留范围外数据，包括最终不满一扇区的 ROM。
- 写入成功前自动回读全量，重放同一个补丁计划及 checksum；扩容部分以 FF 为底
  应用补丁。普通独立校验仍逐字节比较原文件，不偷偷修正文件。
- 进度 0–80% 为写入，80–100% 为自动校验。`write_time_ms` 只计编程，
  `verify_time_ms` 单列校验，`task_time_ms` 包含完整工作任务。任务前的补丁
  规划及请求处理仅体现在客户端 wall time。重叠的 TF/擦除/编程耗时不能简单相加。
- HTTP 与机身结果页增加相同数据跳过量、已校验量、校验耗时；移除不再使用的
  PSRAM 窗口/固定擦除窗口入口。兼容 API 仍接收旧窗口配置，返回的 `psram_mb`
  不代表新引擎实际缓存分配量。
- GBC 操作结束只释放总线，保持所选 3.3V/5V；原清理流程强制切 3.3V 已去除。
  准备阶段先断电、等待，再开目标电源。`cart_power_mv` 是软件命令记录，不是 ADC。
- TF 上传中断必须结束任务状态并删除未完成文件；烧录任务中上传返回 409。

机身 worker 最低剩余栈 10,160 字节。早期同数据 HTTP 用例为 47.748 秒，

31,263,232 字节，GBC 为 31,399,232 字节；纯编程速率与含擦除/校验的
用户总等待时间必须分开理解。

### 数据正确性回归

- GBA 在地址 20003 放入脏字节，避开旧四点采样，再写空白目标。
  新算法确实擦除该扇区；自动及独立 128 KiB 比较均通过。
  原始测试文件 header 为 FF，独立期望文件明确包含自动生成的 checksum 04。
- GBC 先在 128 KiB 扇区的地址 120000 放标记，再仅写前 64 KiB、修改地址
  24577；独立比较完整 128 KiB，证实范围外标记被保留。随后恢复原备份。
- Kirby 的匹配导出文件由 `patch-save sbw` 生成，启用无电池和 3 个 WAITCNT
  修改点。原 ROM 已用 SRAM，因此这行不能证明 SRAM 转换；运行时烧录与
  导出文件独立全量比较通过，匹配跳过 655,360 字节。
- Golden Sun 使用 `FLASH_V123`，确实转换为 SRAM，并启用无电池和 15 个
  WAITCNT 修改点。输出从 9,256,960 扩为 9,699,328 字节；使用原文件实时打
  补丁烧录，自动校验以及与新导出的 `.patched-5.gba` 独立比较均通过。
- GBC 5V/3.3V 探测后软件 rail 状态分别保持 5000/3300；电源单元测试覆盖
  两路互斥、先关后开、错误时终止。没有把软件状态写成物理测压结果。

### 中间失败及处置

- 最初 GBC 引擎误用了 GBA 的 `program_buffer_write_bytes`，GBC 此字段为零，
  导致编程片段退化。实测发现后取消任务，修正为 GBC `buffer_write_bytes`，
  增加真实字段组合回归。失败数据在 `write_v113_gbc_force.jsonl`，不能作为
  最终版速度；最终 `write_v113_gbc_force_final.jsonl` 完整恢复并两次校验通过。
- 32 MiB TF 参考文件上传超过客户端 90 秒超时，旧状态滞留 receiving；该次
  GBC seed 请求在访问卡带前被拒绝。修复上传生命周期后，小参考文件完成同一
  边界验证。主动断开短 HTTP body 的测试返回 500、ERROR、upload interrupted；
  烧录中上传返回 409，均有独立记录。
- 首次中文 Golden Sun `patch-save` 报 open rom for patch plan failed，未访问
  卡带。路径 UTF-8 字节一致，随后相同路径 WAITCNT 分析成功；不据此臆断编码
  或硬件原因，也未增加自动重试/降频。
  后续单独重新执行同一路径 `patch-save sbw` 成功（84.203 秒），并完成上述
  烧录及独立校验；首次打开失败的原因仍未定位，不将一次成功写成根因修复。

## 主机测试和边界

GCC 主机回归通过：`test_sector_plan`、`test_write_pipeline`、
`test_write_expected`、`test_cart_power`、`test_dump_verify`、`test_timing`。
覆盖混合扇区几何、相同/空白/force、非对齐及部分区间、补丁先于比较、
单/双缓存、预取收尾、读/擦/写/取消失败，以及自动校验不匹配不得报成功。
Node Web polling/GB-GBC 补丁隔离测试、共享类型一致性检查和 IDF 编译通过。
主机 expected 测试的补丁应用是 stub，真实补丁正确性以导出文件实机比较补充。

GBA GBX 保留专用配方引擎并接入共同变换/自动校验，但本轮未对 GBX、Intel
芯片或其它卡型做实机写入资格验证。构建有一个未使用几何 helper 警告；
没有将编译/模型测试描述成所有硬件都已验证。
