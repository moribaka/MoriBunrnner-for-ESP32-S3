# v2.32.115：撤回烧录引擎重写

用户要求优化独立校验和 dump，反对把正常烧录改成写前逐扇区内容比较。
v114 仅撤回烧后校验，未撤回该主流程；v115 完整撤回该烧录引擎改动。

## 恢复范围与证据

以下文件经 `git diff --exit-code 641f4e6 -- <paths>` 核对无差异：

- `burner_gba_burn.c`、`burner_gbc_burn.c`：原有 direct、PSRAM 大窗口及 pipeline 实现。
- `burner_burn_common.c`：原有 TF 预取任务创建、同步和收尾方式。
- `burner_gba_flash_lowlevel.c`：原有 GBA 空白抽样及擦除策略。
- `.web/main.html`、`main/ui.c`：原窗口控制与机身 UI。
- `burner_dump_stream.c`、`burner_verify_stream.c`：保留此前已完成的独立 dump/校验优化。

其它烧录数据路径辅助文件及状态布局也已按该提交恢复。
删除新增的 `burner_write_pipeline.c`、`burner_write_expected.c`、
`burner_sector_plan.h` 及依赖该引擎的测试。它们可以从历史提交找回。
`write_matched_bytes`、写前完整内容比较、共享双扇区引擎和额外 source/header
准备阶段均已移除。写后自动校验和 80/20 进度分段仍不存在。

这是恢复原策略，包括原有空白抽样行为，不宣称同时解决了历史空白抽样局限。
原始 Bacon、CPLD 连续传输协议和 AG32 batch 未修改，SPI 仍为 40 MHz。

## 独立保留的修复

相对 `641f4e6`，生产代码仅保留已验证的电源和上传修复：
电源准备先释放总线，互斥切换电源轨；结束访问只释放总线，保持用户选定电压；
SWD 使软件电源状态失效。HTTP `cart_power_mv` 是最后成功命令值，不是测压值。
TF 上传失败会正确结束 receiving 状态并删除未完成文件，烧录中上传返回 409。
这些修复不再带入新的卡带内容比较/擦写安排。

  切压延时、PSRAM 窗口、读取块；返回主页，无烧录/补丁任务运行。

- 当前游戏与 v114 留存备份在地址 0xA0 不同（4D->47）。本轮只读预检和
  卡带识别，没有擦除/编程卡带，没有用旧备份覆盖当前游戏；不提供新的烧录速度结论。
- 最后恢复测试前的 auto 协议偏好，其余路径/窗口/擦除/电压设置未更改。
