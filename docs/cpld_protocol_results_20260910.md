# BSC1 纯 CPLD 协议实机对比（2026-09-10）

已通过实机烧录和全量校验，原卡 32 MiB 内容已恢复。
最终同一 ESP 固件、同一 AG32 位流、同一卡带、同一原始 ROM 的对照中，
新协议编程速度为原 Bacon 的 **2.04 倍**，
整个烧录任务耗时减少 **27.7%**。

## 最终实测

时间单位为秒；每行均强制擦除并独立全量校验。
前两行用于同条件协议对照，后两行用于不同 ROM、补丁和写入流程覆盖。

32 MiB 原始 ROM 的有效编程速度：
原 Bacon **0.737 MiB/s** →
CPLD 连续 **1.503 MiB/s**。
全量校验耗时减少 **30.4%**。
物理擦除仍约 38 秒，因此任务总时间的改善幅度小于纯编程阶段。

编程时间取串口 `program_reports.program_ms`；HTTP `write_time_ms` 是 TF 阶段时间。
Pipeline 擦除取 HTTP `erase_time_ms`，不能取仅覆盖首段的串口 erase 值。
任务时间不含任务启动前的补丁规划；例如黄金太阳组合补丁的客户端启动至
烧录结束墙钟约 40.565 秒，其中设备烧录任务为 19.295 秒。
验证是单独任务，未混入烧录任务时间。

## 延迟与执行归属

- 256 次原 Bacon 单字读取：最终 ESP 固件中位数 **36 μs**、P95 **38 μs**。
- 暂停 AG32 MCU 后，CPLD 连续读取 **8×64 KiB** 全部通过，MCU 随后正常恢复。
- 512 KiB 连续检查：ESP 接收优化前 258.717 ms，优化后 **204.719 ms**。
  最后一轮首缓冲就绪为 **393 μs**；它包含整块预取，不是单字访问延迟。
- 短访问继续原 Bacon；大块数据走 CPLD 双缓冲和本地 NOR 完成检测。
  MCU 不执行数据搬运、卡带时序或逐页轮询。

## 固件和条件

SPI 固定 **40 MHz**，AG32 系统固定 **150 MHz**，没有降频。
卡带 ID 为 `89 00 7E 22 28 22 01 22`，CFI AMD 128 MiB，
128 KiB 扇区、1024 字节编程缓冲、word-address / low-lane、无 D0-D1 交换。
所有最终行使用同一块卡；不混用此前另一张 512 字节缓冲卡的成绩。

## 故障和边界记录

初版下降沿 MISO 返回曾出现 BA CE → FA CE 位错误，长读失败，未用于写卡。
现版采用原 Bacon 的采样后上升沿更新下一位方式，完成本表全部校验。
零延迟及假设 14 ns 回程预算的仿真通过；该预算不是实测板上延迟。
没有用重试、降频或写入途中切换协议处理故障。

地球冒险3 的 SRAM＋无电池＋WAITCNT 组合在导出阶段因 32 MiB 内空间不足
被正常拒绝，没有写卡；改用可容纳组合补丁的黄金太阳进行对应覆盖。
补丁镜像仅用于校验，游戏内实际游玩/存档行为不在本表结论内。
