# AG32 更新流程修复与实机验证

对应 `ag32_startup_flow_audit_20260910.md` 的启动/退出缺陷。
修复位于 ESP32，AG32 MCU/CPLD batch 沿用已验证工件，未修改 Bacon 线协议。

## 实现

- AG32 编程使用开机创建的常驻任务，8 KiB 内部静态栈及静态互斥锁。
  启动只提交路径和通知，保留原有作业互斥，不再动态分配任务栈或作业对象。
- 原生 UI 的验证/启动接入已有 16 KiB 文件工作任务，移除 6 KiB 临时任务；
  后台 ROM 预览可以被 AG32 请求取消，旧预览不会阻塞更新。
- GPIO1 是软件控制的 CS1/SWDIO，GPIO2 是 SWCLK；SPI 的 SCK/MOSI/MISO 不参与 SWD。
  接管时保留 SPI bus/device，只在锁内交接 GPIO；所有 SPI 事务入口检查 SWD 状态。
  不再通过删除设备、释放总线来切换模式，消除该路径的半初始化状态。
- GPIO 接管失败执行明确回滚；回滚或恢复失败进入阻止 SPI 恢复的状态。
  已进入恢复状态时，下一次更新不能在完成验证前恢复旧程序运行。
- Batch 在接管 SWD 前完整载入 PSRAM，关闭 TF 文件后从不可变内存流解析、编程、校验。
  文件大小有上限，flash 地址检查字对齐及擦除起始地址对齐。
- 已尝试暂停但尚未擦写时，失败退出会恢复 MCU，并确认运行状态；恢复失败单独报告，
  保留 SWD 恢复状态。擦写开始后的失败不会继续启动不完整固件。
- 成功重置后确认 MCU 运行，再恢复 SPI 引脚和访问，并使卡带/协议探测缓存失效。
- 保留首次错误、失败阶段、当前字/扇区地址及 SWD ACK；传输读取失败不再伪装为 CRC 不匹配。
  清理错误单独报告，原始错误不会被覆盖。HTTP/串口输出包含这些字段和栈余量。
- 修正 TF 忙碌拦截：此前发送 503 成功后返回 ESP_OK，调用方可能继续执行；
  现在发送拒绝响应后返回错误，调用方立即退出。网页 SWD 探测也拒绝活动中的更新/烧录。
- 更新期间维持既有最大 CPU 性能档，并暂停息屏。SPI 仍为 40 MHz，SWD delay 仍为 1 us。

## 主机验证

`tests/ag32_program_host` 编译实际编程实现和 SPI/SWD 状态转换代码，使用外设故障注入。
18 个分配/文件/接管/连接/暂停/ID/解锁/擦除/编程/校验/重置/恢复/成功/快照场景通过。
检查包括：未擦写失败恢复运行、恢复失败维持保护、擦写后失败不恢复运行、首次错误及 ACK
不被清理覆盖、成功恢复，以及在接管后移除原文件仍能用快照完成编程。
静态任务只创建一次，重复提交和 USB/烧录忙碌提交被拒绝。

SPI/SWD 测试覆盖接管成功、GPIO 失败回滚、回滚失败、恢复保护、成功退出和恢复失败。
Batch parser 测试（含未对齐地址拒绝）、ESP-IDF 构建及双系统分区容量检查也通过。
主机测试不模拟电气时序或 NOR 物理擦写行为；MinGW 内存流替身仅用于测试。

## 实机验证

ESP32-S3 COM26，MAC `a4:cb:8f:f2:c4:c0`，本轮 HTTP `192.168.1.134`。
ESP 应用通过 esptool 写入 0x20000，收到 `Hash of data verified`。
最终已刷应用版本字符串：`v2.32-108-gb7f098c-dirty`。

旧固件经音乐操作后实测内部空闲 22559 字节、最大连续块 10240 字节。
此时旧 6 KiB → 8 KiB 动态任务交接具有真实内存压力；本轮不宣称捕获了用户此前那次首发错误。

新固件进行了两组各 20 次的连接/暂停/读取 ID/恢复检查，均成功。
另验证不存在文件失败的 phase=load、error=ESP_ERR_NOT_FOUND、未擦写且无需恢复；
失败之后继续提交有效更新正常。

三次完整更新均使用 TF 文件 `/sdcard/ag32_cpld_posedge_20260910.bin`，
已下载核对 SHA256 与发布 batch 一致：

| 实刷 | 入口/条件 | 写入 / 校验字节 | 最低栈余量 | 结果 |
| --- | --- | --- | ---: | --- |
| 1 | 串口 | 108924 / 108924 | 4540 B | 成功 |
| 2 | 机身系统设置 UI | 108924 / 108924 | 4508 B | 成功 |
| 3 | 机身 UI，保留暂停音乐资源 | 108924 / 108924 | 4460 B | 成功 |

第三次启动前内部空闲仅 13439 字节、最大连续块仅 **7680 字节**，
仍正常启动和完成，不依赖临时申请 8192 字节任务栈。
每次都确认 DP=2ba01477、device=40200001、records=3、state=success、
error/cleanup_error=ESP_OK、mcu_resumed=true、recovery_required=false。

机身默认取消、B 取消、A 选择取消均未启动更新；确认后更新成功。
刷写中 B/Menu/Right 未离开页面；重复更新请求返回 409，TF 列表返回 503，网页 SWD 探测返回 409。
三次刷后均能再次读取 CPLD 能力并探测 MCU。

首轮之后，测试脚本用上下键导航系统图标网格未找到设置，触发脚本断言；
改为左右键后继续完成两次原生 UI 刷写。这不是固件刷写失败，未自动重试失败的更新。

刷后回归：原 Bacon 256 次 MCU 暂停读取通过，中位 36 us；
CPLD 8×64 KiB MCU 暂停比较通过，MCU 正常恢复。
与 `/sdcard/ROM_OUTPUT/ui_worker_before_20260910.gba` 的 **32 MiB 全量比较通过**，
33554432/33554432 字节一致，设备任务时间 23338 ms。卡带内容未被本轮改写。
最后恢复 ag32_link=auto、智能擦除，停止测试音乐，机身回到主菜单，无活动任务。

原始证据：`ag32_update_flow_fix_20260910.serial.log` 包含全部三次实刷；
`ag32_update_flow_fix_20260910.json` 包含后两次原生 UI 结果及低内存快照；
`ag32_update_flow_after32_20260910.jsonl` 和相应串口日志记录刷后全量比较。
