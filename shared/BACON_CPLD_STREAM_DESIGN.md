# 纯 CPLD 连续传输协议 BSC1

状态：RTL、ESP32 驱动已实现，功能仿真通过；实机资格和速度见
`docs/cpld_stream_implementation_20260910.md`。SPI 固定 40 MHz，系统 150 MHz。

## 执行归属

小于 2048 字节的普通读取、MBC 寄存器访问沿用原 Bacon 编码；大块读写使用
本扩展。两者均由 CPLD 驱动卡带，不依赖 MCU 执行指令。ESP32 负责文件、
PSRAM、补丁、描述符和数据校验。板载 SWD 更新 AG32 的功能保留。

默认物理配置 `ENABLE_MCU_TRANSPORT=0`，不综合实验 MCU 数据通路，以满足
AG32 资源容量；MCU 源码仍保留。`legacy` 明确使用原 Bacon，`cpld` 明确使用
本扩展，`auto` 仅允许在开始操作前按能力/烧录算法选择。CRC、NOR 超时或
数据错误均终止当前流，禁止中途切协议或自动重试。

## 模式与片选

两根 CS 均高时发送八字节 `MORI2CPL` 进入，`MORI2LEG` 退出。
模式键出现在有效载荷内不会切模式。退出等待当前 RD/WR 脉冲完整结束。
进入模式后先读身份，确认再发描述符。两个 CS 的电平约定：

| CS0 | CS1 | 含义 |
| --- | --- | --- |
| 1 | 1 | 空闲 / 模式键 |
| 0 | 1 | 描述符或写数据 |
| 1 | 0 | 读数据 |
| 0 | 0 | 状态 |

原 Bacon 编码不变。CS 分段只结束物理包，地址和总长度在 CPLD 内持续保存。
SPI mode 0：上升沿接收，下降沿更新 MISO。RX 字节经握手跨入系统时钟域。

## 描述符：20 字节

多字节数值为小端。CRC 使用 IEEE CRC32，反射多项式 `0xedb88320`，
初值及末尾异或均为 `0xffffffff`。

| 字节 | 内容 |
| --- | --- |
| 0..3 | `BSC1`，小端整数 `0x31435342` |
| 4 | 1=GBA 读；2=GBA 原始写；3=GBA AMD 缓冲编程；4=GB 读；5=GB 原始写；6=GB AMD 缓冲编程 |
| 5 | 保留，必须为 0 |
| 6..7 | 编程页掩码：页字节数减 1；普通读写传 0 |
| 8..11 | 起始字节地址 |
| 12..15 | 总字节数 |
| 16..19 | 前 16 字节的 CRC32 |

GBA 地址、长度必须偶数，不能跨 32 MiB 窗口；GB 不能跨 64 KiB 物理地址窗口。
bank 切换需先结束流，再通过 Bacon 向实体卡带的 MBC 写入。
编程页大小必须为 2 的幂：GBA 2..1024 字节，GB 2..256 字节。
描述符长度、字段、范围及 CRC 错误在触发卡带写入前拒绝。

## 数据包与缓冲

两个 1024 字节物理 BRAM 缓冲，按顺序交替使用。一页编程时可接收下一页，
CRC 全部通过后才允许写该页。主机必须先检查 READY，不能溢出缓冲。

写入每包的数据量由剩余字节数和页边界推导，无地址/长度头：编程最大为
到当前页末尾的字节数，普通写最大 1024 字节。数据填充到 4 字节对齐，
随后附实际数据（不含填充）的 CRC32。每个 CS 事务一个包。

读取每包最大 1020 字节，最后 4 字节 RAM 存 CRC。主机收到四字节 dummy，
随后是对齐到 4 字节的数据及 CRC32。CRC 不包含填充。每包先查 TX_READY，
再进行一次 CS 事务；当前版本不在同一个 CS 下拼接多个读包。
读包传输完成后才更新已完成字节数；状态查询不消耗读数据。

## 状态：16 字节

| 字节 | 内容 |
| --- | --- |
| 0..3 | dummy |
| 4..6 | `BA CE 01` |
| 7 | bit0 模式；bit1 已配置；bit2 DONE；bit3 ERROR；bit4 RX_READY；bit5 TX_READY；bit6 总线忙 |
| 8..11 | 已完成字节数 LE32 |
| 12..15 | 错误码 LE32 |

错误码：1=CRC 引擎被覆盖；2=接收超长；3=接收状态错误；4=描述符长度/CRC；
5=描述符字段/范围；6=数据长度/CRC；7=读包长度/状态；8=NOR 超时；9=非法状态。
错误锁存到退出模式。DONE 要求所有数据已经执行，主机核对完成量等于总量。

## 卡带时序和算法

GBA 复用地址总线，GB 单独推进地址。RD 低 24 个系统周期，WR 低 8 个周期，
建立/恢复阶段各 8 个周期。AMD 标准缓冲编程在 CPLD 内产生
unlock/count/data/confirm，并在最后一个地址两次连续读取到完整目标值后
确认完成；每页 watchdog 为 150000000 周期。擦除及特殊芯片配方仍由既有
Bacon 算法执行。ESP 的显式 CPLD 烧录在擦除前拒绝不支持的芯片配方。

时序仿真、布线时序、暂停 MCU 后读取、32 MiB 全量校验和实机烧录速度是
不同的验证项目。不得把理论 SPI 带宽当成 NOR 烧录速度。
