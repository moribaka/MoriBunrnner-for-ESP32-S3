# 纯 CPLD 连续传输设计

状态：协议设计稿，尚未实现到 CPLD 位流。当前已实现的主路径是原 Bacon；
本文件不把之前的 MCU Stream 当成新的 Bacon 硬件协议。

## 主路径与分工

低延迟单字访问、MBC 寄存器写入继续使用原 Bacon 编码，一次 SPI 事务由
CPLD 直接执行。大块访问新增 CPLD 连续模式。MCU 不负责接收数据、解析
数据包、翻转卡带控制信号或响应每块数据；暂停 MCU 时两条主路径也必须可用。

ESP32 负责 ROM 文件、PSRAM 窗口、补丁和上层流程；CPLD 负责地址游标、
卡带 RD/WR 时序、数据 FIFO，以及连续 NOR 编程需要的页命令与完成检测。
板载 SWD 刷 AG32 的能力保留。MCU 实验协议只能显式启用。

## 进入和控制

旧 Bacon 线上编码保持不变。扩展使用独立的硬件模式键 `MORI2CPL`（8 字节，
两根 CS 均为高时发送）。`MORI2LEG` 退出。进入后先读取 CPLD 身份/版本，
成功确认后才发送可能操作卡带的命令。查询用不拉低 RD/WR 的安全 MOSI 值；
未识别扩展时，只能在操作开始前选用旧 Bacon，不能在写入中途换协议。

控制描述符固定 16 字节、小端：

| 字节 | 内容 |
| --- | --- |
| 0..1 | 描述符标识 |
| 2 | 操作：ROM 读、总线写、GB 读写、AMD 缓冲编程 |
| 3 | 版本/显式选项 |
| 4..7 | 起始字节地址 |
| 8..11 | 总字节数 |
| 12..13 | NOR 页缓冲字节数；普通读写为 0 |
| 14..15 | 描述符 CRC16 |

地址和总长度只在逻辑传输开始时给出。SPI 的 CS 分段不结束逻辑传输，
后续 DMA 块不重复地址或长度。字节数据不能被当成操作码。
GB 的 MBC bank 写入仍是明确的物理操作；GBA 流不能越过 32 MiB 窗口，
GB 流不能跨过本次指定的物理地址窗口。越界在执行前拒绝。

## 数据执行

- 读取：CPLD 预取、移位输出，并直接推进卡带读地址；满足 FIFO 条件后才
  声明 READY。SPI 暂停时保持游标，不靠 MCU、RTOS tick 或固定软件延时。
- 普通总线写：数据字由 CPLD 产生 WR 脉冲，按协议定义递增地址。
  GBA 地址复用和 GB 显式地址推进分别实现。
- NOR 编程：不是把 32 MiB 当成一次 NOR 写。CPLD 按芯片页边界产生
  unlock/count/data/confirm，检测 NOR 完成，然后推进页地址。
  ESP32 不再为每个 512 字节页生成整段 Bacon 指令。
- 至少双缓冲：一页被编程时，另一页接收后续 SPI 数据。SPI 接收与卡带
  操作真正重叠；之前仅用于移位发送的两个字寄存器不算这种流水线。
- 数据块只保留必要的校验，不携带地址、长度、重复命令。
  状态分别报告可接收空间、已接收量和已完成编程量；完成不等于收到 SRAM。
  主机按 FIFO 空间发送有界 DMA 块，不能要求 SPI 从机凭空暂停主机时钟。

NOR 内部编程与擦除耗时仍存在。协议优化的目标是降低 SPI 数据展开、
主机调度和 MCU 执行开销，而不是宣称提高 NOR 的物理编程速度。

## 实现顺序与通过条件

1. 固定主路径为 Bacon/CPLD，排除默认 MCU 协商和请求缓冲分配。
   用暂停 MCU 的实机读取及单字延迟记录证明执行归属。
2. CPLD 增加连续读/普通写状态机、计数器和小 FIFO；验证 CS 暂停、末字、
   状态查询不消耗数据、过量发送及数据中包含模式键。
3. 实现页级 NOR 编程硬件状态机及双缓冲流控。描述符错误不得触发 WR；
   接收异常或 NOR 超时明确结束操作，不重试、不切换后端掩盖失败。
4. 完整构建、容量/时序审查，再在 40 MHz 下比较相同卡带、ROM、擦除条件。
   分别记录单字/首字延迟、连续吞吐量、编程累计和整个任务时间，并全量校验。

当前位流占用 1392/2112 逻辑、98/132 tiles，BRAM 未使用。扩展需要实际综合
确认资源和时序，不能把这份预算当成新增状态机一定放得下的结论。
延迟和吞吐量均以实测为准；不降低默认 SPI 或 MCU 时钟。
